# Google Apps Script 受信側セットアップ

配送アプリから日報・納品明細・社内作業・メモを受信し、Googleスプレッドシートへ保存するWeb Appです。`DEVICE_KEY`や受信本文はログへ記録しません。

## 1. スプレッドシートとApps Scriptを用意する

1. 提供済みのダッシュボード用Googleスプレッドシートを開きます。別環境で始める場合は、空のGoogleスプレッドシートでも構いません。
2. URLの `/d/` と `/edit` の間にあるIDを控えます。
3. スプレッドシートの「拡張機能」→「Apps Script」を開きます。
4. このディレクトリの `Code.gs` を、Apps Scriptエディタの `Code.gs` へ貼り付けて保存します。
5. Apps Scriptプロジェクトのタイムゾーンを `Asia/Tokyo` に設定します。

## 2. Script Propertiesを設定する

Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」に以下を登録します。

| プロパティ | 値 |
|---|---|
| `SPREADSHEET_ID` | 手順1で控えたスプレッドシートID |
| `DEVICE_KEY` | 16文字以上の十分に長いランダム文字列 |

`DEVICE_KEY`は公開HTML、Git、CSV、JSONバックアップへ書かず、配送アプリの連携設定画面だけに入力してください。

## 3. 初期化する

1. Apps Scriptエディタ上部の関数選択で `initializeWorkbook` を選びます。
2. 「実行」を押し、スプレッドシートへのアクセスを許可します。
3. スプレッドシートに次の6シートが作成されたことを確認します。
   - ダッシュボード
   - 日報
   - 納品明細
   - 作業明細
   - メモ
   - 同期ログ
4. ダッシュボードの対象月が `YYYY-MM` 形式で表示され、KPI・比較表・2つのバブルチャート・上位作業の週別折れ線グラフが作られていることを確認します。

`initializeWorkbook`はダッシュボードを作り直します。運用開始後に再実行すると、ダッシュボードへ手動で加えた編集は消えるため注意してください。データ5シートの実データ行は消しませんが、検証用テンプレートに含まれる `SAMPLE-` で始まるサンプル行だけは自動で除去します。ヘッダーが想定と異なる場合は安全のため `HEADER_MISMATCH_*` で停止します。

## 4. Web Appとしてデプロイする

1. 「デプロイ」→「新しいデプロイ」を選びます。
2. 種類は「ウェブアプリ」を選びます。
3. 「次のユーザーとして実行」は **自分** を選びます。
4. 「アクセスできるユーザー」は、静的な配送アプリから利用できる範囲（通常は **全員**）を選びます。
5. デプロイし、表示された `/exec` のWeb App URLを配送アプリへ設定します。
6. 配送アプリの端末キーには、Script Propertiesの `DEVICE_KEY` と同じ値を入力します。

Web App URLを知る第三者からの送信は端末キーで拒否されます。ただしURL自体と端末キーは機密情報として扱い、共有しないでください。スプレッドシート本体の共有範囲は本人のみにします。

## API

POST本文はJSONで、`api_version`（固定値 `1`）、`action`、`request_id`、`device_key`、`entity`を送ります。操作は次の4種類です。

- `upsert_report`
- `delete_report`
- `upsert_note`
- `delete_note`

同じ`request_id`で処理済みの送信は重複登録されず、`duplicate: true`で成功します。日報の再送時は日報行を更新し、紐づく納品・作業明細を最新内容へ置き換えます。

状態確認は `GET ?request_id=...&callback=...` のJSONPです。返す情報は `processed` / `pending` / `error` と処理日時だけで、日報本文、端末キー、エラー詳細は返しません。

## 運用確認

- 新規日報を保存し、日報・納品明細・作業明細・同期ログへ反映されること
- 同じ日報を更新し、子明細が重複せず置き換わること
- 同じ`request_id`を再送し、行が増えないこと
- 出発より帰社が早い時刻の日報で、配送時間が日またぎとして計算されること
- 時刻不足時は配送時間が空欄になること
- 複数タグの社内作業が1行・1回分の時間として保存されること
- 不正な端末キーが `UNAUTHORIZED` で拒否されること

コード更新後は「デプロイを管理」から新しいバージョンを作成し、既存デプロイをそのバージョンへ更新してください。
